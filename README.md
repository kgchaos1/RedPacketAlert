# 红包提醒（RedPacketAlert）

一个基于 **NotificationListenerService** 的 Android 通知增强工具：监听微信的系统通知（**包括被折叠的群聊**），
一旦在通知文本里发现「红包」等关键词，就发出**自定义强提醒**——响铃、持续震动、闪光灯闪烁、悬浮窗弹窗、点亮屏幕。

> 群折叠了、通知不显示详情、消息列表看不到，都不影响：只要微信把通知推给系统，本应用就能读到并判断。

---

## 1. 它解决什么问题

微信把不常看的群折叠之后，这些群的消息只在通知栏里一闪而过，很容易错过红包。
红包消息在微信通知里的文本形态通常是：

| 场景 | 通知标题 | 通知正文 |
| --- | --- | --- |
| 普通群 + 红包 | 群名 | 张三: [微信红包] 恭喜发财 |
| 折叠群 + 红包 | 微信 / 折叠的群聊 | [微信红包] 或 张三: [微信红包] |
| 单聊 + 红包 | 好友昵称 | [微信红包] |

本应用把这些字段（标题、正文、大字文本、子文本、文本行、MessagingStyle 消息、Android 11+ 的会话标题）
全部收集起来做关键词匹配，命中后触发一套比系统通知强得多的提醒。

## 2. 工作原理

```text
微信 post 通知
      │
      ▼
NotificationListenerService.onNotificationPosted(sbn, rankingMap)   ← 系统级权限，折叠群同样会推送
      │
      ▼
NotificationParser  ──  抽取 title / text / bigText / subText / textLines /
      │                 MessagingStyle messages / conversationTitle / ticker
      ▼
RuleEngine（纯 Kotlin，可单测）
      ├─ 总开关、监控包名、常驻通知、系统静音过滤
      ├─ 关键词命中（忽略空格/大小写）+ 排除词
      ├─ 免打扰名单 → 直接跳过
      ├─ 白名单（按群名 / 发送者昵称匹配，群名不可识别时可配置放行）
      └─ 去重窗口 + 最小提醒间隔（防止同一条通知反复触发、消息风暴连环炸）
      │
      ▼
AlertController ── 声音（循环，可走闹钟音量通道）
                ├─ 持续震动（波形循环，到点自动停）
                ├─ 闪光灯闪烁（CameraManager.setTorchMode）
                ├─ 悬浮窗卡片（含“打开微信 / 我知道了”，可点亮屏幕）
                └─ WakeLock 点亮屏幕
```

## 3. 功能一览

- **通知监听**：系统级 NotificationListenerService，覆盖所有应用（默认只处理微信）。
- **关键词过滤**：默认 `红包`、`紅包`、`[微信红包]`、`微信红包`，可增删；另有排除词（默认 `红包封面`）。
- **白名单 / 免打扰名单**：只监听特定群或屏蔽特定群；群名读不到时可以回退到「发送者昵称」匹配。
- **强提醒方式**：铃声（可自选、循环播放、走闹钟音量流）、持续震动、闪光灯闪烁、悬浮窗、点亮屏幕，全部可独立开关。
- **提醒时长**：3~60 秒可调，到点自动停止，也可在悬浮窗上点「我知道了」立即停止。
- **去重与限流**：同一条通知重复推送不会重复响；最小提醒间隔可调。
- **事件日志**：记录最近 200 条「已提醒/未提醒」及原因，方便排查为什么没响。
- **零网络**：应用不申请 INTERNET 权限，不联网、不上传任何内容。

## 4. 构建与安装

### 直接装 APK

自己构建后，产物在：

```text
app/build/outputs/apk/debug/app-debug.apk
```

用数据线或文件传输装到手机上即可（需要允许「安装未知来源应用」）。

> 仓库不存放二进制产物（`dist/`、`build/` 均被忽略）。要分发给别人，建议把 APK 上传到 GitHub Releases。

### 从源码构建

需要 JDK 17 和 Android SDK（platform 34 + build-tools 34.0.0）：

```bash
# 设置 SDK 路径（二选一）
echo "sdk.dir=/path/to/Android/Sdk" > local.properties
export ANDROID_HOME=/path/to/Android/Sdk

./gradlew assembleDebug        # 产出 APK
./gradlew testDebugUnitTest    # 跑规则引擎单元测试
```

工程使用 AGP 8.5.2 + Kotlin 1.9.24 + Gradle 8.7，minSdk 26（Android 8.0）、targetSdk 34。

## 5. 首次使用（务必按顺序授权）

1. 打开应用 → **通知使用权** 点「去开启」→ 找到「红包提醒」→ 允许。
   （不同 ROM 路径：设置 → 通知 → 通知使用权 / 通知读取权限）
2. **悬浮窗权限** 点「去开启」→ 允许「显示在其他应用上层」。不开也能用，只是没有弹窗。
3. **电池优化** 点「去开启」→ 允许后台运行。再在系统设置里给本应用加锁/自启动白名单
   （MIUI / EMUI / ColorOS / OriginOS 等国产 ROM 尤其重要）。
4. 打开「启用红包强提醒」开关。
5. 点「测试提醒」，确认铃声/震动/闪光灯/弹窗符合预期。

## 6. 设置说明

**提醒方式**
- 声音提醒：循环播放所选铃声。
- 使用闹钟音量通道：走 `USAGE_ALARM`，在手机静音或勿扰模式下也能响（**强提醒**的关键）。
- 持续震动：波形循环，直到提醒结束或被关闭。
- 闪光灯闪烁：调用 `CameraManager.setTorchMode`，不需要相机权限；相机被占用时会自动跳过。
- 悬浮窗弹窗：全屏遮罩 + 卡片，显示群名/发送者/消息内容/命中关键词，可一键打开微信。
- 点亮屏幕：提醒期间持有屏幕 WakeLock。
- 提醒持续时间：3~60 秒。

**关键词**
- 匹配关键词：命中任意一个即触发。比较时会去掉所有空白和零宽字符，并忽略大小写。
- 排除关键词：命中即忽略（默认排除「红包封面」，否则每次有人发红包封面都会响）。
- 忽略常驻通知：过滤「正在进行中」的通知。
- 忽略被系统静音的通知：按 RankingMap 的 `isSuspended` 判断，默认关闭以免漏报。

**群聊范围**
- 只提醒白名单里的会话：开启后，不在名单里的会话一律不提醒。
- 白名单 / 免打扰名单：群名、联系人昵称都可以，支持部分匹配（名单项 ≥ 2 个字）。
- 同时按发送者昵称匹配名单：折叠群只显示「张三: [微信红包]」时非常有用。
- 群名无法识别时仍然提醒：微信折叠/聚合通知可能完全不给出群名，开启此项则照常提醒（推荐）。

**高级**
- 监控的应用包名：默认 `com.tencent.mm`（微信），理论上可加其他应用。
- 最小提醒间隔：默认 2 秒，避免一次消息风暴里连环轰炸。
- 事件日志：看历史判定结果，包含「未提醒」的原因。

## 7. 能力边界（请务必了解）

本应用只能处理**微信已经推送到系统的通知**。以下情况任何第三方应用都无能为力：

- 在微信里彻底关闭了「接收新消息通知」；
- 微信判定你正在看该聊天（前台会话）而不发通知；
- 系统层面把微信的通知整个屏蔽（如「通知类别」被关）；
- 手机深度休眠 + 厂商激进杀后台，微信没能及时推送（需把微信和本应用都加入后台白名单）。

另外：

- 走「闹钟音量通道」时，声音大小由**闹钟音量**决定，请确认闹钟音量不为 0。
- 悬浮窗需要「显示在其他应用上层」权限；部分 ROM 还需要额外允许「后台弹出界面」。
- 本应用**不修改、不拦截、不自动抢**微信的任何内容，只做「读通知 → 提醒」，完全本地运行。

## 8. 常见问题

**Q：测试提醒有反应，但真实红包不响？**
看「事件日志」：
- 完全没有记录 → 微信没发通知（见第 7 节），或通知使用权被系统回收。
- 记录里是「未命中任何关键词」→ 你的微信版本通知文本里没有「红包」两字，把日志里的原文复制进「匹配关键词」。
- 记录里是「会话不在白名单内」→ 关掉白名单，或把日志里显示的群名/昵称加进白名单。
- 记录里是「重复推送已去重」→ 正常，说明同一条通知被微信重复 post 了。

**Q：会不会误报？**
「红包」是宽松匹配，群名或聊天内容含「红包」也会触发。用「排除关键词」和「白名单」收敛即可。

**Q：耗电吗？**
不监听网络、不轮询、不常驻前台服务（NotificationListenerService 由系统绑定托管），只在通知到达时做一次字符串匹配，开销极低。

**Q：为什么没有用前台服务保活？**
通知监听服务由系统绑定，被杀后系统会在新通知到来时重新拉起，比自建前台服务更省电也更稳定。
